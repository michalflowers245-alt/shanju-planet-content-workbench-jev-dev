# 闪聚星球内容工作台-JEV-开发

这是当前工作台的公开源码副本，仓库名为 `shanju-planet-content-workbench-jev-dev`。保留前后端、启动脚本、数据库结构、内容处理规则和自动化测试；不包含任何用户业务数据库、已抓取正文/图片、登录态、API 密钥、运行日志或私人交付报告。

从源码运行会建立新的本地数据目录，不会自带原工作台的账号资料或历史内容。模型连接、平台登录和可选的 JEV Key 需要由使用者自行配置。请勿将 `.workbench/`、`database/` 或完整数据交付压缩包上传到公开仓库，详见 [公开仓库安全说明](SECURITY.md)。

采集完整度取决于平台当前可访问内容：登录、安全验证、删除或权限限制必须如实保留，**不承诺任意帖子 100% 可抓取**。原始发布正文、摘要、字幕和 ASR 分开保存，不能互相冒充。

一个本地使用的极简自媒体文案产品。普通文案任务默认自动进行主题、受众、业务三个方向的公开联网研究，再经过三员工流程完成：

```text
研究员联网研究、核对来源并拆题 → 文案员工按人设与因果结构写稿 → 主编真实局部编辑并复核 → 最终文案
```

## 使用

需要 Python 3.10+、Node.js 与 npm；平台采集另需本机 Google Chrome。请先完成前端构建，再启动后端：

```sh
python -m venv .venv
# macOS / Linux；Windows 使用 .venv\Scripts\activate
source .venv/bin/activate
python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
python -m backend.app.main
```

完成前端构建后，macOS 可双击 `启动 AI 文案工作台.command`，Windows 可双击 `启动文案工作台.bat`。macOS 启动器会寻找 Python 3.10 或更高版本、建立独立的 `.venv` 并安装依赖。公开源码不附带 `frontend/dist`、依赖或桌面快捷方式；本地数据交付包与本仓库是两种不同用途的产物。默认打开 `http://127.0.0.1:5191`，并使用 8789 模型代理端口和 9230 采集浏览器端口；端口可用环境变量覆盖。不要同时启动占用相同端口的另一份工作台。

首次使用时进入“设置”，任选一种模型连接：

- **本机 OpenAI OAuth 代理**：填写本机 OpenAI-compatible 代理根地址与模型名称，再点击“测试并保存”。工作台会先读取代理 `/v1/models` 的真实列表，确认模型存在后才进行生成测试。代理应先在本机完成自己的 OpenAI OAuth 登录；工作台只向 `http://127.0.0.1`、`localhost` 或 `::1` 发起请求，OAuth Token 始终留在代理里。
- **DeepSeek API**：选择 `deepseek-v4-flash`（更快）、`deepseek-v4-pro`（更强）或图片案例用的 Vision 模型，填入 DeepSeek API Key 并点击“测试并启用 DeepSeek”。工作台固定连接官方 `https://api.deepseek.com`，只有测试成功后才把 Key 存入当前 Mac 的系统钥匙串；Key 不会写入文案、日志、SQLite 数据库或导出包。本机 OAuth 代理会保留，可随时重新测试并切回。

连接测试成功后，研究员、文案员工和主编才会使用当前模型；代理未运行、尚未完成 OAuth 登录、DeepSeek Key 无效或模型名称不正确时，设置页会给出明确原因。公开研究并行使用搜狗网页、Bing 新闻 RSS、Bing 网页 RSS 和品牌资料库，不依赖模型侧联网工具。普通文案任务会自动以“主题事实、受众处境、业务关联”三组查询搜索，去重后整理最多 20 条来源；搜索无结果时仍可继续写观点稿，但界面会明确显示“联网受限”，不把本地资料冒充为外部证据，事实性表述按待核实边界处理。研究包会拆出推荐角度和因果论证，写稿与主编都能读取；主编实际执行局部真人化编辑，结果页可查看选题与逻辑拆解及来源适配说明。生活案例朋友圈继续仅依据用户提供的文字和图片事实，不联网搜索。

## 四个内容工作台

- 朋友圈自动运营：输入本轮主题，生成连续 3、7 或 14 天的发布时间、内容角色、完整正文和互动承接。
- 生活案例朋友圈：上传 1–9 张生活图片并写下事情经过，生成“真实日常”“有感而发”“轻度业务启发”三篇可直接发布的朋友圈文案。
- 小红书 IP 文案：提供主题，自动读取“我的 IP 信息”，交付标题、正文、标签和可一键复制的发布版。
- 抖音情感文案：选择共鸣、治愈、遗憾、成长或关系清醒，生成约 30、60 或 90 秒的情感口播。

四种模式都不会补造经历、案例和效果；主编会确定性检查朋友圈周期、生活素材事实边界、小红书发布包和抖音前 3 秒情绪现场。

创作输入框下方的“没灵感？试试”会按当前内容模式显示 3 条灵感。点击“换一批”可从该模式的 15 条候选中继续轮换；朋友圈、小红书和抖音分别维护自己的灵感池。

生活案例朋友圈的完整操作、图片隐私和失败恢复说明见 [生活案例朋友圈工作台说明](docs/生活案例朋友圈工作台说明.md)。

## 内容雷达：每天找方向，主题搜完就创作

内容雷达提供两种入口。正式主题搜索会批量采集并去重；本轮实时核验的候选都可独立进入串行正文/媒体归档，随后由 JEV 按人设与业务分类为 A/B/C。分类路由控制推荐优先级，不再限制哪些候选能读正文。每批可按单一账号人设采集 200、300 或 500 条候选；JEV 按每 3 条候选组成一次结构化请求，分类规则和隐私边界见 [JEV 批量内容研究说明](docs/JEV批量内容研究说明.md)。

抖音详情采用登录后的本机专用浏览器按真实视频 ID 逐篇读取。本轮实时核验的抖音候选均可进入串行正文队列（每批最多 500 条），不会并发轰击平台；A/B/C 决定内容推荐优先级，不决定是否读取候选正文。结构化详情里的完整发布文案标为“已核验完整发布文案”，页面可见字段标为部分结果。若本机简体中文模型已就绪，工作台会尝试读取当前登录会话可访问的公开视频媒体，在本机临时目录离线转写后立即删除媒体，只保存 ASR 文本和文件哈希；发布文案、平台字幕和口播转写仍分开保存。采集浏览器卡片还可将历史 caption-only 详情补回转写队列。`COMPLETE` 只表示平台发布文案完整，不表示平台全站或口播全文绝对完整。

如果自动媒体读取不可用，可在已核验的抖音详情卡导入一份你有权处理的本机音/视频文件。macOS 26+ 使用 Apple SpeechAnalyzer 在本机离线识别简体中文；临时媒体处理完成后删除，只保存转写、来源标记和 SHA-256。自动路径只使用专用 Chrome 当前登录会话和 allowlist 中的媒体地址，不读取 Cookie、不保存签名 URL；媒体不可访问、播放列表或平台限制会显示失败原因，绝不绕过登录/验证码。机器转写须人工核对，不能作为平台原始字幕或全站全量保证。

两种入口是：

- **每日 IP 热点**：从当前工作区已填写的人设、受众和内容方向出发，用本机浏览器读取双平台搜索结果，再用 JEV 判断人设匹配、业务匹配、内容价值和风险；A 类用于优先推荐，详情归档与分层独立。
- **主题搜索后创作**：输入任意主题，批量读取小红书笔记与抖音视频当前可见的标题、文案摘要、作者、原文链接和可见互动数；本轮真实候选可排队读取详情，JEV 则按当前人设和业务边界分流，A 类优先推荐，B/C 留存复核或不推荐。

当前工作台的浏览器采集方式需要用户在专用 Chrome 中登录平台；不会借用其他工作台登录态、导出 Cookie 或绕过验证码。2026-09-23 已核验免个人账号登录的有限路径：抖音官方搜索接口可使用应用级 `client_token`，但需开放平台应用及搜索权限；小红书当前没有核实到任意公开笔记的官方搜索/读文接口，第三方服务声称可通过自有 API Key 提供搜索和正文，需另行核实授权、覆盖与费用。任何方式都不能保证全站全量或每条视频完整口播。若使用浏览器，遇到登录墙或安全验证会明确提示；任一平台读取失败时，不会用历史缓存或公开索引冒充实时内容。完整边界见 [JEV 批量内容研究说明](docs/JEV批量内容研究说明.md) 与 [内容雷达接入说明](docs/内容雷达接入说明.md)。

小红书结果卡现在会区分“搜索页摘要”“旧页面证据”和“严格归档”。点击“保存原图与正文”，工作台会在已登录的专用 Chrome 中核对帖子 ID，分别保存未改写的原始正文与规范化正文，并按轮播顺序保存浏览器实际返回的图片字节。只有身份、正文、预期图片数量、全部图片和校验清单均通过时才显示 `COMPLETE`；部分结果可以继续补齐，后续失败不会覆盖旧的完整归档。图片 OCR、页面字幕和 ASR 只作为辅助证据，不会冒充原始正文。

每日热点会分别显示小红书与抖音本轮筛出的数量。每次刷新展示本轮页面快照：即使某篇帖子以前见过，只要本轮页面仍真实返回，就继续显示，并用 `NEW` 区分是否首次出现。系统先排除和主题不够相关的结果，再按搜索页真实显示的点赞、评论、收藏、转发或播放等互动数据排序；平台页面没有展示的指标不会补造。

## 本机只读 MCP：给外部模型读取工作台数据

工作台附带 `scripts/mcp/matchmaking_readonly_mcp.py`。支持 MCP 的客户端可以通过标准输入输出读取当前工作区、品牌资料、文案任务、内容雷达、资料库、发布数据、生活案例摘要，以及已验证的小红书正文与图片证据。服务使用 SQLite 只读连接和固定查询工具，不提供任意 SQL、写入、删除、发布或登录能力；密钥字段会脱敏，访问元数据写入 `.workbench/mcp_audit.log`。配置示例和安全边界见 [相亲工作台只读 MCP 接入说明](docs/相亲工作台只读MCP接入说明.md)。

推荐的协作方式是：GPT‑6 Pro 通过只读 MCP 读取真实数据并完成深度分析与执行规划；在支持“添加到 Codex”的界面中把计划交给 Codex；执行任务选择 GPT‑6 Astra、推理强度 High，在独立工作树中实现、测试并提交。完整操作见 [GPT‑6 Pro、MCP 与 Codex 执行工作流](docs/GPT-6-Pro-MCP到Codex执行工作流.md)。

## 当前界面

- 开始创作：选择朋友圈运营、生活案例朋友圈、小红书或抖音工作台，并查看三名数字员工的真实进度。
- 内容雷达：本机可见浏览器读取小红书与抖音搜索结果，每日按 IP 生成最多 12 个方向，临时主题搜完即可创作。
- 作品记录：查看定稿、处理中和需要处理的任务；生活案例还支持素材预览、继续生成、归档和恢复。
- 设置：连接本机 OpenAI OAuth 代理或 DeepSeek API、查看公开搜索源/资料库状态、三个 Skill 的实际加载版本并维护“我的 IP 信息”。

旧作品和其他已有文案类型继续保存在作品记录中，但首页只突出这四个核心产品，避免再次变成功能堆砌。

隔离交付的默认代理地址为 `http://127.0.0.1:8789/v1`，默认模型为 `gpt-5.6-luna`。启动器会同时拉起只监听本机的 Codex OAuth 兼容代理；它通过已登录的 Codex 会话完成模型调用，工作台本身不读取会话 Token。研究、写稿、主编和改写阶段均使用 `reasoning_effort=max`。联网研究优先使用平台后台采集；若平台登录或安全验证未完成，工作台会暂停对应阶段并要求用户处理，不会静默降级成历史内容。

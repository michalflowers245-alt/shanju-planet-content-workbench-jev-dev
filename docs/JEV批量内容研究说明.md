# JEV 批量内容研究

## 工作流

主题搜索、每日 IP 热点、旧版即时主题搜索和普通内容雷达统一遵循同一条分类边界：

1. 按本批所选账号人设扩展搜索词。
2. 使用本机专用浏览器，在小红书和抖音的隐藏页面采集 200、300 或 500 条候选。
3. 以平台和真实帖子 ID 去重，保存可恢复的本地候选池。
4. 按每 3 条候选组成一个请求，把标题、搜索摘要与公开互动数据交给 TypeSafe JEV 做结构化判断；每条候选仍有独立的问题键和 A/B/C 结果。
5. 应用在本地固定的阈值和风险规则，将候选分到 A、B、C 三类；JEV 评分必须基于标题/摘要所描述的实际语境，不能只凭搜索词重合。
6. 帖子详情归档与 JEV 分层彼此独立：本轮实时核验且去重后的候选都可进入串行正文/媒体读取队列，避免只读取 A 类造成 B/C 样本正文缺失；A/B/C 仍决定创作推荐优先级、风险复核与选题分流。

JEV 只负责语义分类与排序，不负责抓取平台内容，也不能把未验证来源变成 `LIVE_VERIFIED`。平台实时采集完成与 JEV 分类完成是两个独立状态；若任一平台要求安全验证，该平台保留 `USER_ACTION_REQUIRED`，不会提前分类整批候选。平台验证完成后复用同一批次、按真实帖子 ID 去重续跑。B/C 候选仍保留并可深读归档，但不会因为正文归档而自动成为推荐内容。

## 人设与业务约束

每个批次只绑定一个人设，并保存启动时的人设快照。当前内置两个人设：

- 柚子皮在长沙：长沙本地成年单身人群、线下社交和相亲活动、组织者视角。
- 爱牵线的小豆子：社交圈较小的成年单身女性、初次相亲、择偶判断和红娘实用建议。

人设写入现有 `brand_profiles.profile_json` 的 `radar.personas`，没有建立第二份账号画像。分类维度包括人设匹配、业务匹配、内容价值、内容支柱、受众需求以及性别对立、结果承诺、隐私和偏题风险。搜索词只用于说明采集上下文，不作为相关性的独立证据；结果同时保存可见标题/摘要、评分、风险项和理由。当前规则版本为 `matchmaking-radar-v2`。

## A/B/C 规则

- A：人设、业务和内容价值均达到阈值，置信度足够，且没有高风险信号。可作为优先推荐和创作候选。
- B：方向可能有价值，但置信度不足、处于阈值边缘，或 JEV 请求需要重试。保留人工复核，不自动推荐。
- C：明显偏题、与业务不匹配，或出现高概率的对立、虚假承诺、隐私等风险。不作为推荐内容；仍保留分类与归档记录，供排查和完整性核对。

阈值由应用代码确定，JEV 不能自行改变路由规则。每次分类保存模型、规则版本、可见证据、分数、置信度、风险概率和理由，便于追溯。TypeSafe JEV 的结构化接口返回 `noul`、`choice`、`score` 三类答案；工作台根据这些答案、候选标题/摘要和固定阈值生成可核对的理由，不伪称模型返回了自由文本解释。批量请求返回的是整批用量，工作台会在候选间平均拆分用量以保持总量守恒；单条记录中的 token 数是分摊估算，不代表该候选的独立计费量。

## 配置与恢复

在“设置 → TypeSafe JEV 分类器”中填写 API Key。工作台会先调用官方接口验证，再把密钥存入 macOS 钥匙串；SQLite、日志、ZIP 和前端都不会保存明文密钥。

如果尚未配置 JEV，系统会先完成真实候选采集，然后停在 `AWAITING_JEV_KEY`。连接 JEV 后点击“继续本批”，会复用已经完成的查询和候选，不重新采集。平台登录或安全验证会显示 `USER_ACTION_REQUIRED`；只能由用户本人处理，工作台不会绕过验证码或风控。

## 限制

- 搜索页在不同时间可能返回重复或不足的内容，因此目标数是采集上限目标，不是平台结果保证。
- 没有 TypeSafe JEV API Key 时无法进行真实 JEV 分类；工作台不会用本地假结果冒充。
- JEV 接收前会移除链接、手机号和微信号，且不会发送作者名、原帖 URL、Cookie、Token 或浏览器资料。
- 抖音 JEV-A 候选最多 500 条进入本地串行详情队列，队列会保存状态并逐篇处理；不会并发打开页面。遇到登录/验证/平台限制时，会暂停其余队列，用户在平台处理后重新读取成功才继续。候选池是平台本轮实际显示的结果，不代表平台全站全量。

## 抖音正文与完整度

- 登录状态由用户在工作台专用 Chrome 中完成并由本机浏览器配置目录持久保存；工作台不导出或复制 Cookie。
- 进入详情页后必须核对视频 ID。只有详情数据中与目标 ID 一致的结构化发布文案，才标记 `COMPLETE` / “已核验完整发布文案”。标题卡片或页面可见文本只能标记 `PARTIAL`。
- 页面结构化字幕、字幕轨、页面可见字幕和语音识别稿各自独立保存与显示。`COMPLETE` 只表示平台发布文案完整，不表示 ASR 无误或覆盖平台全站。
- 本机简体中文 ASR 已就绪时，A 类作品的详情页会先核对视频 ID，再从页面播放器/结构化播放地址中尝试取得 allowlist 内的可访问媒体；媒体通过 Chrome 当前会话流式写入本机临时目录，完成 ASR 后自动删除。数据库只保存识别文本、来源、时长、大小与媒体哈希，不保存媒体或带签名 URL。
- 浏览器登录后，可在内容雷达的采集浏览器卡片点击“补齐历史抖音口播”，把旧版留下的 caption-only 记录最多 500 条重新送入同一串行队列；已有转写和超过重试次数的记录不会重复抓取。
- 任何登录墙、验证码、平台限流或身份不一致都会停止/暂停，不尝试取 Cookie、调用未授权私有接口或绕安全机制。HLS/DASH 播放列表、不可用媒体、模型未就绪或超过 500MB/15 分钟上限时不会伪造完整口播；可改用详情卡上的本机媒体导入路径。ASR 是机器识别稿，需人工校对，仍与平台原始发布文案/字幕分开。
- 旧的 caption-only 记录最多在后续搜索中自动补试一次；有已有 ASR 的记录不会反复进入媒体队列。

## 免登录采集边界（核验于 2026-09-23）

“不登录个人抖音/小红书账号”不等于“零凭证、全站全量”。搜索结果受关键词、分页、平台授权能力、配额和内容可见范围限制，无法承诺把两站所有文案、选题或视频口播稿完整导出。

- 抖音[公开视频搜索接口](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/douyin-search-capability/aweme-dy-video-search)要求应用级 `client_token`，示例响应包含 `high_quality_text`，但接口需要先创建开放平台应用并获得相应搜索能力；文本字段也不保证每条视频都有完整口播。[Token 文档](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/tutorial/beginner/token)说明 `client_token` 不需要用户授权，但要有平台应用和密钥，因此这不是匿名 API。
- 小红书[开放平台 Scope 文档](https://openaccount.xiaohongshu.com/docs/scope)当前把读取笔记权限列为“规划中”，没有核实到面向任意公开笔记的官方全站搜索/正文接口。第三方服务商（例如 [Rnote 接口说明](https://www.rnote.dev/docs/guide)）声称可以不绑定小红书账号，通过自己的 API Key 搜索公开笔记和取正文；其 API Key、账户和按量计费仍需配置，数据覆盖与平台授权不能仅凭供应商宣传视为保证。
- 未经平台明确许可，不以隐藏接口、模拟账号、绕验证码或规避风控来补齐所谓“全量”。第三方服务须先核实合同、授权来源、字段覆盖、成本和数据用途，再由用户单独确认是否接入。
- JEV 对抓到的公开候选按当前人设与业务进行分层；它不会扩展平台搜索覆盖，也不会把候选变成平台全量数据。

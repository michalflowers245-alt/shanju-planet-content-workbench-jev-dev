# 小红书原帖改写工作台

这条流程从内容雷达里一篇已归档的小红书帖子开始，生成的是一份新的可发布内容包，原帖始终只读。

## 使用方式

1. 在“内容雷达”中打开一篇小红书帖子，先完成“保存原图与正文”。
2. 只有帖子 ID 一致、`body_raw` 已验证时，原帖区域才会出现“按这篇改写成内容包”。OCR、摘要、字幕和旧页面摘录不会作为改写原文。
3. 选择目标平台、改写强度、人设和 3–9 张配图数量，点击开始。
4. 工作台依次完成拆解原帖、确定策略、生成完整文案、策划系列配图、审核。任一环节都可局部重新生成；重做上游环节会使依赖的下游结果重新生成。
5. 在右侧复制或导出 Markdown 内容包。原帖正文、正文哈希、原图数量和归档状态会保留在导出信息中，方便核对来源。

## 五个模型阶段

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| `analysis` | 原帖逐字正文、已保存原图的安全清单、用户选项 | 核心主题、原帖结构、受众情绪、可迁移元素、不能复写的内容 |
| `strategy` | 原帖快照和分析 | 新角度、目标读者、叙事结构、表达规则、事实边界 |
| `copy_generation` | 原帖快照、分析、策略 | 标题、备选标题、完整正文、标签、评论区引导、封面字、正文分段 ID |
| `image_plan_generation` | 文案分段和策略 | `style_bible`、每张图的角色、文案、提示词、关联正文段落和画面说明 |
| `review` | 全部内容包 | 事实边界、相似表达风险、自然表达、平台可读性、图文对应关系的审核结论 |

所有阶段的系统提示词都要求：原帖只能用于理解事实、结构、情绪和视觉线索；不得复写原句、标题句式、段落顺序或作者口吻；不得虚构经历、数据、效果和评论。

## 图片策略

- 原图字节仍由小红书归档保存，改写任务仅保存图片顺序、哈希、尺寸和本机工作台下载地址。
- 当当前模型选择 DeepSeek Vision 时，分析阶段会在内存中读取最多六张缩略视觉参考图；这些预览不写进数据库、日志或导出文件，也不改动归档原图。
- 普通文本模型只会看到图片清单，结果会标记为“仅图片元数据”，不会假称已经看过图片内容。
- `style_bible` 与 `image_cards` 只提供后续图片生成的结构和提示词，不会假装已经生成图片。

## 接口

- `POST /api/rewrite/jobs`
- `GET /api/rewrite/jobs/{id}?workspace_id=...`
- `POST /api/rewrite/jobs/{id}/regenerate`
- `GET /api/rewrite/jobs/{id}/export?workspace_id=...`
- `GET|POST|DELETE /api/topic-radar/favorites`

## 数据与安全

- 每个改写任务冻结 `source_snapshot_json`，归档后来补齐或刷新不会改写已经完成的内容包。
- 收藏是工作区范围内的雷达原帖快照，不会在每日刷新时消失。
- 每日 IP 热点按来源 ID 过滤已经展示过的帖子；没有新帖时明确显示空结果，不回退成旧卡片。
- 迁移使用 `scripts/migrate_rewrite_v1.py --database <隔离数据库副本> --backup <备份路径>`。脚本只做兼容增量、事务和校验，不会自动修改正式桌面版数据库。
